# Phase boundaries

Use a phase boundary when the work changes from reasoning to implementation,
from implementation to review, or from one independent question to another.

1. **Continue** when the next phase needs the current decisions and artifacts.
2. **Compact** when the current context is still relevant but too large to keep
   sharp.
3. **Use a sub-agent** only for a narrow, independently verifiable read or
   analysis whose result can return to the current task.
4. **Start a fresh thread** when the next task has a different objective and
   does not need the current reasoning.

Do not cross a boundary until the current phase has a checkable completion
criterion: a settled decision, a runnable prototype, a passing test slice, or a
review report.
