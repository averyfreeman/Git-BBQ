# Domain docs

This repository is single-context. Before exploring or changing architecture,
read the root `GLOSSARY.md` and the relevant records in `docs/adr/`.

Use glossary terms consistently in issue titles, specs, code comments, and
design notes. If a needed term is missing, add or refine it when the concept is
settled. Surface conflicts with an existing ADR instead of silently replacing
its decision.

Git BBQ-generated projects have a separate established contract: their project
vocabulary remains in `CONTEXT.md` and routing remains in `CONTEXT-MAP.md`.
Do not change that generated-project format as part of repository setup.
